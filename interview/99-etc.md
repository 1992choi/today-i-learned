## 단방향 암호화와 양방향 암호화
- 암호화란?
  - 평문을 특정 키를 사용해서 해독할 수 없는 형태로 변경하는 것을 뜻한다.
  - 암호화 방식에는 단방향 암호화와 양방향 암호화 방식이 있다.
  - ![image](https://github.com/1992choi/today-i-learned/assets/27760576/2a8f6ab3-a3f9-4046-897c-cf182b606f3f)
- 단방향 암호화
  - 평문을 암호화하는 것은 가능하지만 암호문을 평문으로 복호화할 수 없는 기법.
  - 대표적으로 HASH를 사용한 방식이 있다.
- 양방향 암호화
  - 암호문을 평문으로 복호화할 수 있는 기법.
  - 양방향 암호화는 크게 대칭키(비공개키)와 비대칭키(공개키)방식으로 나눠진다.
  - 대칭키 방식은 암호화, 복호화시 모두 동일한 키를 사용하고, 비대칭키(공개키)방식은 암호화 복호화에 서로 다른 키를 사용한다.
   - 대칭키(비공개키) 방식
      - 암/복호화에 서로 동일한 키가 사용되는 암호화 방식.
      - 장점
        - 비대칭키보다 속도가 빠르다.
      - 단점
        - 키를 교환해야하는 키 배송 문제가 발생한다.
        - 키를 교환하는 도중에 키가 탈취될 수 있다.
        - 사람이 증가할수록 각자 따로 키를 교환해야하므로 관리해야할 키가 방대해진다.
      - 종류
        - AES, DES 알고리즘
    - 비대칭키(공개키) 방식
      - 암/복호화에 다른 키가 사용되는 방식
      - 노출시켜도 상관없는 Public Key와 노출시켜서는 안되는 Private Key로 구성된다.
      - 장점
        - 공개키는 공개되어있기 떄문에 키 교환이 필요없다.
        - 개인키를 가지고 있는 수신자만이 복호화할 수 있으므로 인증 기능을 할 수 있다.
      - 단점
        - 대칭키 방식에 비해 속도가 느리다.
      - 종류
        - RSA 알고리즘

## 고정 소수점과 부동 소수점
- 실수의 표현 방식
  - 컴퓨터에서 실수를 표현하는 방법에는 크게 고정 소수점 방식과 부동 소수점 방식이 있다.
- 고정 소수점 방식
  - 정수를 표현하는 비트와 소수를 표현하는 비트 수를 미리 고정하고 해당 비트만을 활용하여 실수를 표현한다.
    - ![image](https://github.com/1992choi/today-i-learned/assets/27760576/3eb00f8f-fde6-4719-89d4-dd01b6553b85)
    - 처음 1비트는 sign(부호)을 나타낸다. (0은 양수, 1은 음수)
    - 다음 15비트는 integer part(정수부)를 나타낸다.
    - 다음 16비트는 fractional part(소수부)를 나타낸다.
  - 장점
    - 표현하는 방법이 단순하다.
    - 연산속도가 빠르다.
  - 단점
    - 표현할 수 있는 범위가 적다.
    - 정밀도가 낮다.
- 부동 소수점 방식
  - 정수를 표현하는 비트와 소수를 표현하는 비트 수가 유동적이다.
    - ![image](https://github.com/1992choi/today-i-learned/assets/27760576/e1c374d0-b98e-4924-ae1d-e4a053110623)
    - 2진수를 정규화 한다.
    - 처음 1비트는 sign(부호)를 나타낸다. (0은 양수, 1은 음수)
    - 다음 8비트는 exponent(지수부)를 나타낸다.
    - 다음 23비트는 mantissa(가수부)를 나타낸다.
  - 장점
    - 더 큰 실수를 표현할 수 있다.
  - 단점
    - 실수 연산이 부정확할 수 있다.
      - 예를 들어 십진수 0.3을 2진수로 변환하면 0.0100110011...(2) 처럼 특성 수가 무한이 반복된다. 따라서 컴퓨터가 실수 부분을 표현할 수 있는 비트 수를 다 써버리게 되어 근사치로 표현되게 된다.
- 부동 소수점의 저장
  - 부동 소수점은 근사값으로 표현되기 때문에 오차가 발생하기도 한다.
    - JAVA에서의 오차 해결
      - BigDecimal 클래스를 사용한다.
    - DB에서의 오차 해결
      - DECIMAL타입을 사용하여 부동 소수점을 고정 소수점 방식으로 사용한다.

## 빅오 표기법(Big-O Notation)
- 빅오 표기법이란?
  - 입력값(n)이 커질 때, 알고리즘의 실행 시간(또는 사용하는 메모리)이 얼마나 증가하는지를 표현하는 점근적 표기법이다.
  - 실제 실행 시간(초 단위)이 아니라, 입력 크기가 커질수록 연산 횟수가 어떤 비율로 늘어나는지를 나타내어 알고리즘의 효율성을 비교하는 데 사용된다.
  - 최악의 경우(Worst Case)를 기준으로 표현하는 것이 일반적이며, 이를 통해 알고리즘이 보장하는 성능의 상한선을 알 수 있다.
- 왜 정확한 연산 횟수가 아니라 점근적 표기를 사용하는가?
  - 하드웨어 성능, 프로그래밍 언어, 구현 방식에 따라 정확한 실행 시간은 달라지므로, 절대적인 시간보다는 입력 크기 증가에 따른 증가 추세(경향성)를 비교하는 것이 알고리즘 자체의 효율성을 평가하는 데 더 의미가 있다.
  - 입력값이 충분히 커졌을 때는 최고차항 이외의 항(낮은 차수의 항, 상수항, 계수)이 전체 증가 추세에 미치는 영향은 미미해지므로, 빅오 표기법에서는 최고차항만 남기고 나머지는 무시한다. (예: 3n² + 5n + 100 → O(n²))
- 대표적인 시간 복잡도 (빠른 순서)
  - O(1) - 상수 시간 : 입력 크기와 무관하게 항상 일정한 시간이 걸린다. (예: 배열의 인덱스 접근, HashMap의 조회)
  - O(log n) - 로그 시간 : 입력 크기가 커져도 연산 횟수가 매우 천천히 증가한다. (예: 이진 탐색, 균형 이진 탐색 트리에서의 검색)
  - O(n) - 선형 시간 : 입력 크기에 비례해서 연산 횟수가 증가한다. (예: 배열을 처음부터 끝까지 순회)
  - O(n log n) - 선형 로그 시간 : 정렬 알고리즘에서 흔히 나타난다. (예: 병합 정렬, 퀵 정렬의 평균 시간)
  - O(n²) - 이차 시간 : 입력값 하나마다 나머지 전체를 다시 순회하는 경우 발생한다. (예: 이중 for문을 사용하는 버블 정렬, 완전 탐색)
  - O(2ⁿ) - 지수 시간 : 입력이 하나 늘어날 때마다 연산량이 두 배로 늘어난다. (예: 재귀로 구현한 피보나치수열, 부분집합을 모두 구하는 완전 탐색)
- 공간 복잡도(Space Complexity)
  - 알고리즘이 실행되는 동안 추가로 사용하는 메모리 공간의 양을 나타내며, 시간 복잡도와 마찬가지로 빅오 표기법으로 나타낸다.
  - 입력값을 저장하기 위한 공간은 제외하고, 알고리즘이 추가로 사용하는 공간(재귀 호출 스택, 임시 배열 등)만을 기준으로 계산하는 것이 일반적이다.
  - 시간 복잡도와 공간 복잡도는 흔히 트레이드오프 관계에 있는데, 예를 들어 이전에 계산한 값을 배열(메모)에 저장해두고 재사용하는 메모이제이션(Memoization) 기법은 공간을 더 사용하는 대신 시간 복잡도를 줄이는 대표적인 예시이다.
- 시간 복잡도와 실제 성능의 차이
  - 빅오 표기법은 입력이 매우 커졌을 때의 증가 추세를 나타낼 뿐이므로, 입력값이 작을 때는 이론적으로 더 느린 시간 복잡도를 가진 알고리즘이 실제로는 더 빠를 수도 있다. (예: 데이터가 적을 때는 O(n²)인 삽입 정렬이 O(n log n)인 퀵 정렬보다 상수 계수나 캐시 지역성 덕분에 더 빠른 경우가 있다.)
  - 따라서 실제 성능을 판단할 때는 빅오 표기법뿐만 아니라, 실제 데이터 규모와 하드웨어 환경(캐시 효율, 메모리 접근 패턴 등)도 함께 고려해야 한다.

## 데이터의 표현 (이진수, 2의 보수, 문자 인코딩)
- 컴퓨터의 데이터 표현
  - 컴퓨터는 모든 데이터(숫자, 문자, 이미지 등)를 0과 1로 이루어진 이진수(Binary)로 표현하고 저장한다.
- 음수의 표현과 2의 보수(Two's Complement)
  - 컴퓨터가 뺄셈을 별도의 회로 없이 덧셈 회로만으로 처리할 수 있도록, 음수를 표현하는 대표적인 방식이 2의 보수이다.
  - 어떤 수의 2의 보수는, 해당 수의 1의 보수(모든 비트를 반전)를 구한 뒤 1을 더해서 구한다. (예: 4비트에서 5(0101)의 2의 보수는 1010 + 1 = 1011, 즉 -5를 의미한다.)
  - 2의 보수를 사용하면 "A - B"라는 뺄셈 연산을 "A + (B의 2의 보수)"라는 덧셈 연산으로 그대로 처리할 수 있어, CPU가 덧셈기(Adder) 하나만으로 덧셈과 뺄셈을 모두 수행할 수 있다는 장점이 있다.
  - 부호를 나타내는 비트가 하나뿐인 1의 보수 방식과 달리, 2의 보수 방식에서는 0이 단 하나(0000)만 존재해 표현의 모호함이 없다는 점도 장점이다.
- 문자 인코딩(Character Encoding)과 디코딩(Decoding)
  - 문자 역시 결국 숫자(이진수)로 저장되어야 하므로, 어떤 문자를 어떤 숫자에 대응시킬지 정의한 규칙이 필요한데 이를 인코딩이라 하고, 반대로 저장된 숫자를 다시 문자로 해석하는 과정을 디코딩이라 한다.
  - ASCII: 영문 알파벳, 숫자, 특수문자 등을 7비트(128개)로 표현하는 초기 표준이지만, 한글이나 다른 언어의 문자는 표현할 수 없다는 한계가 있다.
  - 유니코드(Unicode): 전 세계 모든 문자를 하나의 표준 체계로 표현하기 위해 만들어진 문자 집합으로, 각 문자에 고유한 코드 포인트를 부여한다.
  - UTF-8: 유니코드를 실제로 저장/전송할 때 사용하는 대표적인 인코딩 방식으로, 문자에 따라 1~4바이트의 가변 길이를 사용한다. 영어와 같은 ASCII 문자는 1바이트로 표현되어 기존 ASCII와 호환되면서도, 한글 등의 문자는 3바이트로 표현해 다양한 언어를 효율적으로 지원한다.
  - 인코딩 방식이 서로 다른 시스템 간에 데이터를 주고받으면 문자가 깨지는 "인코딩 깨짐" 현상이 발생할 수 있어, 송수신 양쪽의 인코딩 방식을 일치시키는 것이 중요하다.

## 명령어 구조와 주소 지정 방식
- 명령어(Instruction)란?
  - 고급 언어로 작성된 소스 코드는 컴파일러에 의해 CPU가 이해할 수 있는 기계어(Machine Code) 명령어로 변환되며, CPU는 이 명령어를 하나씩 읽어 해석하고 실행한다.
- 명령어의 구조
  - 명령어는 크게 연산 코드(Operation Code, Opcode)와 오퍼랜드(Operand)로 구성된다.
  - 연산 코드는 덧셈, 뺄셈, 데이터 이동 등 수행할 연산의 종류를 나타내고, 오퍼랜드는 연산에 사용할 데이터 또는 그 데이터가 저장된 위치(레지스터, 메모리 주소 등)를 나타낸다.
- 주소 지정 방식(Addressing Mode)
  - 오퍼랜드에 데이터의 실제 위치를 어떤 방식으로 표현할지를 정의한 것으로, 대표적으로 다음과 같은 방식들이 있다.
    - 즉시 주소 지정(Immediate Addressing): 오퍼랜드 자체에 사용할 데이터 값이 직접 담겨 있는 방식이다. 메모리 접근이 필요 없어 가장 빠르지만, 표현할 수 있는 값의 크기가 명령어 길이에 의해 제한된다.
    - 직접 주소 지정(Direct Addressing): 오퍼랜드에 실제 데이터가 저장된 메모리 주소를 직접 명시하는 방식이다.
    - 간접 주소 지정(Indirect Addressing): 오퍼랜드가 가리키는 메모리 위치에는 실제 데이터가 아니라 데이터가 저장된 또 다른 주소가 담겨 있는 방식이다. 메모리 접근이 한 번 더 필요해 느리지만, 더 넓은 범위의 메모리 주소를 표현할 수 있다.
    - 레지스터 주소 지정(Register Addressing): 오퍼랜드가 데이터가 저장된 레지스터를 가리키는 방식으로, 레지스터는 CPU 내부에 있어 메모리보다 훨씬 빠르게 접근할 수 있다.
- CISC와 RISC
  - CISC(Complex Instruction Set Computer): 복잡하고 다양한 기능을 수행하는 명령어를 지원해, 적은 수의 명령어로도 복잡한 작업을 처리할 수 있지만 명령어의 실행 시간이 제각각이라 파이프라이닝 등 최적화가 어렵다. (예: x86)
  - RISC(Reduced Instruction Set Computer): 단순하고 크기가 일정한 명령어만 지원해, 명령어 하나의 실행 속도는 빠르고 파이프라이닝 최적화가 쉽지만 복잡한 작업을 위해서는 더 많은 명령어 조합이 필요하다. (예: ARM)

## CPU 구성과 명령어 처리 (레지스터, 명령어 사이클, 인터럽트, 파이프라이닝, 비순차적 실행)
- CPU의 핵심 구성 요소
  - ALU(Arithmetic Logic Unit, 산술논리연산장치): 사칙연산이나 비교, 논리 연산(AND, OR 등) 등 실제 연산을 수행하는 장치이다.
  - 제어장치(Control Unit): 명령어를 해석하고, 그 명령어를 수행하는 데 필요한 제어 신호를 CPU 내부 및 다른 장치(메모리 등)에 전달하는 장치이다.
  - 레지스터(Register): CPU 내부에 있는 매우 빠르지만 용량이 작은 임시 저장 공간이다. 프로그램 카운터(PC, 다음에 실행할 명령어의 주소), 명령어 레지스터(IR, 현재 해석 중인 명령어), 범용 레지스터(연산에 사용할 데이터) 등 다양한 종류가 있다.
- 명령어 사이클(Instruction Cycle)
  - CPU가 하나의 명령어를 처리하는 기본 과정으로, 크게 인출(Fetch, 메모리에서 명령어를 읽어옴) → 해독(Decode, 명령어를 해석) → 실행(Execute, 실제 연산 수행) → (필요시) 저장(Write-back, 결과를 레지스터/메모리에 반영)의 단계를 반복한다.
- 인터럽트(Interrupt)
  - CPU가 현재 실행 중인 작업을 잠시 멈추고, 우선적으로 처리해야 할 다른 이벤트를 처리하도록 하는 신호이다.
  - 하드웨어 인터럽트: 타이머, 키보드, 디스크 등 하드웨어 장치가 CPU에 비동기적으로 보내는 신호이다.
  - 소프트웨어 인터럽트(트랩): 프로그램이 시스템 콜을 호출하거나 예외 상황(0으로 나누기 등)이 발생했을 때 명시적으로 발생시키는 인터럽트이다.
  - 인터럽트가 발생하면 CPU는 현재 상태(레지스터 값 등)를 저장한 뒤 해당 인터럽트를 처리하는 루틴(Interrupt Service Routine)을 실행하고, 완료되면 원래 작업으로 복귀한다.
- 명령어 병렬 처리 - 파이프라이닝(Pipelining)
  - 하나의 명령어 처리 과정(인출-해독-실행-저장)을 여러 단계로 나누고, 각 단계를 서로 다른 하드웨어 유닛이 동시에 처리하도록 하여 마치 공장의 조립 라인처럼 여러 명령어를 겹쳐서 처리하는 기법이다.
  - 명령어 하나를 처리하는 데 걸리는 시간(Latency) 자체는 줄지 않지만, 여러 명령어를 동시에 처리할 수 있어 전체적인 처리량(Throughput)이 크게 향상된다.
  - 파이프라인 위험(Hazard): 데이터 위험(이전 명령어의 결과에 의존하는 경우), 제어 위험(분기 명령어로 인해 다음에 실행할 명령어를 예측해야 하는 경우), 구조적 위험(동일한 하드웨어 자원을 여러 단계가 동시에 사용하려는 경우) 등으로 인해 파이프라인이 멈추거나(Stall) 잘못된 결과가 나올 수 있어, 분기 예측(Branch Prediction) 등의 기법으로 이를 완화한다.
- 비순차적 명령어 처리(Out-of-Order Execution)
  - 프로그램에 작성된 순서가 아니라, 준비된(의존성이 해소된) 명령어부터 먼저 실행해 CPU의 유휴 시간을 줄이는 기법이다.
  - 다만 실행 결과를 프로그램 상의 순서와 동일하게 보이도록, 최종 결과를 반영(Commit/Retire)하는 시점은 원래의 순서를 지킨다.

## 멀티코어와 멀티프로세서
- 멀티코어(Multi-core)란?
  - 하나의 CPU 칩(패키지) 안에 독립적으로 명령어를 처리할 수 있는 코어(Core)를 여러 개 포함시킨 구조이다.
  - 각 코어는 독립된 ALU, 레지스터, (보통) L1/L2 캐시를 가지지만, L3 캐시나 메모리 컨트롤러 등은 여러 코어가 공유하는 경우가 많다.
- 멀티프로세서(Multi-processor)란?
  - 하나의 시스템(메인보드)에 물리적으로 별도의 CPU 칩을 여러 개 장착한 구조를 뜻하며, 각 CPU가 멀티코어인 경우도 흔하다.
- 멀티코어/멀티프로세서를 사용하는 이유
  - 하나의 코어(단일 스레드) 성능을 높이는 데는 발열, 소비전력 등 물리적인 한계가 있기 때문에, 코어 수를 늘려 여러 작업을 동시에(병렬로) 처리함으로써 전체 처리량을 높이는 방향으로 발전해왔다.
  - 다만 코어가 많다고 무조건 성능이 비례해서 좋아지는 것은 아니며, 프로그램이 병렬로 처리 가능한 구조(멀티스레드 등)로 작성되어야 여러 코어의 이점을 실제로 누릴 수 있다.
- 대칭적 멀티프로세싱(SMP)과 캐시 일관성
  - 여러 코어(프로세서)가 동일한 메모리를 공유하는 구조를 대칭적 멀티프로세싱(Symmetric Multi-Processing, SMP)이라 한다.
  - 각 코어가 독립된 캐시를 가지고 있으면, 같은 메모리 주소의 데이터가 코어마다 서로 다른 캐시에 저장된 채 값이 달라지는 캐시 불일치(Cache Incoherence) 문제가 발생할 수 있는데, 이를 해결하기 위해 MESI 프로토콜과 같은 캐시 일관성(Cache Coherence) 프로토콜을 하드웨어적으로 사용한다.

## 메모리 계층구조와 캐시 메모리
- 메모리 계층구조(Memory Hierarchy)란?
  - 속도가 빠르지만 용량이 작고 비싼 저장장치(레지스터, 캐시)부터, 속도는 느리지만 용량이 크고 저렴한 저장장치(보조기억장치)까지 계층적으로 구성한 구조이다.
  - 레지스터 → L1/L2/L3 캐시 → 메인 메모리(RAM) → 보조기억장치(SSD/HDD) 순으로 내려갈수록 속도는 느려지고 용량과 저장 비용은 늘어난다.
  - CPU가 원하는 데이터를 매번 느린 메인 메모리나 디스크에서 가져온다면 CPU의 빠른 처리 속도를 낭비하게 되므로, 자주 쓰는 데이터를 상대적으로 빠른 계층(캐시)에 미리 올려두어 평균 접근 속도를 끌어올리는 것이 메모리 계층구조의 핵심 아이디어이다.
- 캐시 메모리(Cache Memory)란?
  - CPU와 메인 메모리 사이의 속도 차이를 줄이기 위해, CPU에 더 가깝고 빠르지만 용량은 작은 저장 장치에 자주 사용하는 데이터를 임시로 저장해두는 메모리이다.
- 캐시가 동작할 수 있는 이유 - 지역성의 원리(Locality)
  - 시간 지역성(Temporal Locality): 최근에 접근한 데이터는 가까운 미래에 다시 접근될 가능성이 높다. (예: 반복문에서 매번 참조되는 변수)
  - 공간 지역성(Spatial Locality): 어떤 데이터가 접근되면, 그 데이터와 인접한 주소의 데이터도 곧 접근될 가능성이 높다. (예: 배열 순회) 이 때문에 캐시는 데이터를 한 바이트씩이 아니라, 캐시 라인(Cache Line)이라는 일정 크기의 블록 단위로 가져온다.
- 캐시 히트(Hit)와 캐시 미스(Miss)
  - 캐시 히트: CPU가 필요로 하는 데이터가 캐시에 이미 존재하는 경우로, 빠르게 데이터를 가져올 수 있다.
  - 캐시 미스: 캐시에 데이터가 없어 메인 메모리까지 가서 데이터를 가져와야 하는 경우로, 상대적으로 큰 지연이 발생한다.
- RAM과 ROM
  - RAM(Random Access Memory): 전원이 꺼지면 데이터가 사라지는 휘발성(Volatile) 메모리로, 실행 중인 프로그램과 데이터를 저장하는 메인 메모리로 사용된다.
  - ROM(Read Only Memory): 전원이 꺼져도 데이터가 유지되는 비휘발성(Non-volatile) 메모리로, 부팅 시 필요한 펌웨어(BIOS 등)와 같이 변경할 필요가 없는 데이터를 저장하는 데 사용된다.
- 리틀 엔디안과 빅 엔디안
  - 여러 바이트로 이루어진 데이터를 메모리에 저장할 때, 바이트를 나열하는 순서를 정의한 방식이다.
  - 빅 엔디안(Big Endian): 사람이 숫자를 쓰는 방식과 동일하게, 최상위 바이트(MSB)부터 낮은 주소에 저장한다. 네트워크 프로토콜에서는 관례적으로 빅 엔디안을 표준(Network Byte Order)으로 사용한다.
  - 리틀 엔디안(Little Endian): 최하위 바이트(LSB)부터 낮은 주소에 저장하는 방식으로, x86/x64 계열 CPU에서 주로 사용된다.
  - 서로 다른 엔디안 방식을 사용하는 시스템 간에 데이터(특히 네트워크로 전송되는 바이너리 데이터)를 주고받을 때는, 바이트 순서를 서로 맞춰주는 변환 작업이 필요하다.
- 캐시 친화적인 코드(Cache-friendly Code)
  - 공간 지역성을 최대한 활용하도록, 메모리에 연속적으로 배치된 데이터를 순차적으로 접근하는 방식으로 코드를 작성하면 캐시 미스를 줄여 성능을 높일 수 있다. (예: 2차원 배열을 순회할 때, 메모리에 저장된 순서(Row-major order 기준으로는 행 우선)에 맞춰 접근하는 것이 그렇지 않은 경우보다 훨씬 빠르다.)

## 보조기억장치와 RAID, 디스크 스케줄링
- 보조기억장치(Secondary Storage)란?
  - 메인 메모리(RAM)와 달리 전원이 꺼져도 데이터가 유지되는 비휘발성 저장장치로, 대표적으로 하드디스크(HDD)와 SSD(플래시 메모리 기반)가 있다.
- HDD(Hard Disk Drive)
  - 자기 디스크(Platter)를 물리적으로 회전시키고, 헤드(Head)를 이동시켜 데이터를 읽고 쓰는 기계식 저장장치이다.
  - 헤드가 원하는 위치까지 이동하는 탐색 시간(Seek Time)과 디스크가 회전해 원하는 섹터가 헤드 위치에 도달하는 회전 지연(Rotational Latency)이 발생해, 물리적인 이동이 필요 없는 SSD보다 느리다.
- SSD(Solid State Drive)
  - 플래시 메모리 기반으로, 기계적으로 움직이는 부품 없이 전기적으로 데이터를 읽고 쓰는 저장장치이다.
  - HDD에 비해 훨씬 빠른 속도와 낮은 소비전력, 높은 내구성(충격에 강함)을 가지지만, 동일 용량 기준으로 가격이 더 비싸고 쓰기/삭제 횟수에 물리적인 한계(Wear Leveling으로 수명을 관리)가 있다.
- RAID(Redundant Array of Independent Disks)
  - 여러 개의 물리적인 디스크를 하나의 논리적인 디스크처럼 묶어, 성능 향상이나 데이터 안정성(중복성)을 확보하는 기술이다.
  - RAID 0(스트라이핑): 데이터를 여러 디스크에 나누어 동시에 읽고 쓰기 때문에 속도는 빠르지만, 디스크 하나만 고장 나도 전체 데이터가 손실되어 안정성은 없다.
  - RAID 1(미러링): 동일한 데이터를 여러 디스크에 중복해서 저장해 안정성은 높지만, 실제 사용 가능한 용량은 디스크 개수의 절반 수준으로 줄어든다.
  - RAID 5: 데이터를 여러 디스크에 분산 저장하면서, 패리티(Parity, 오류 복구를 위한 정보)를 함께 분산 저장해 디스크 하나가 고장 나도 나머지 디스크와 패리티로 데이터를 복구할 수 있다. 성능과 안정성, 용량 효율의 균형이 좋아 널리 사용된다.
- 디스크 스케줄링(Disk Scheduling)
  - 여러 개의 디스크 입출력 요청이 동시에 들어왔을 때, 헤드의 이동 거리를 최소화해 탐색 시간을 줄이기 위한 순서를 결정하는 정책이다.
  - FCFS(First Come First Served): 요청이 들어온 순서대로 처리하는 가장 단순한 방식이지만, 헤드가 비효율적으로 왔다갔다할 수 있다.
  - SSTF(Shortest Seek Time First): 현재 헤드 위치에서 가장 가까운 요청부터 처리해 탐색 시간을 줄이지만, 멀리 있는 요청은 계속 밀려 기아(Starvation) 상태에 빠질 수 있다.
  - SCAN(엘리베이터 알고리즘): 헤드가 디스크의 한쪽 끝에서 반대쪽 끝까지 이동하면서, 그 경로상에 있는 모든 요청을 처리하고 끝에 도달하면 방향을 바꾸는 방식으로, 엘리베이터가 움직이는 방식과 유사하다.
  - C-SCAN: SCAN과 유사하지만, 헤드가 끝에 도달하면 반대 방향으로 서비스하지 않고 곧바로 시작 지점으로 되돌아가 다시 같은 방향으로만 처리해, 요청 간 대기 시간의 편차를 좀 더 균등하게 만든다.

## GPU와 병렬 프로그래밍 (CUDA)
- CPU와 GPU의 구조적 차이
  - CPU는 복잡한 분기 처리와 순차적인 연산에 최적화된, 적은 수의 강력한 코어로 구성되어 있어 다양한 종류의 작업을 빠르게 처리하는 데 유리하다.
  - GPU(Graphic Processing Unit)는 상대적으로 단순한 연산을 수행하는 수천 개의 작은 코어로 구성되어 있어, 동일한 연산을 대량의 데이터에 동시에 적용하는 데 특화되어 있다.
- 병렬성과 동시성
  - 병렬성(Parallelism)은 여러 작업을 물리적으로 동시에(같은 순간에) 실행하는 것을 뜻하고, 동시성(Concurrency)은 여러 작업이 번갈아 실행되며 마치 동시에 실행되는 것처럼 보이는 것을 뜻한다.
  - 싱글 코어 CPU에서 여러 스레드를 빠르게 번갈아 실행하는 것은 동시성의 예시이고, GPU에서 수천 개의 코어가 각각 실제로 동시에 연산을 수행하는 것은 병렬성의 예시이다.
- GPU가 병렬 연산에 유리한 이유
  - 이미지 처리, 행렬 연산, 딥러닝의 학습/추론과 같은 작업은 동일한 연산(예: 곱셈-덧셈)을 수많은 데이터에 대해 독립적으로 반복 수행해야 하는데, 이런 연산 패턴을 SIMD(Single Instruction Multiple Data)라 하며 GPU의 구조와 잘 맞아떨어진다.
  - 반면 조건 분기가 많거나 순차적 의존성이 강한 연산은, 단순한 코어를 많이 가진 GPU보다 복잡한 제어 로직을 갖춘 CPU가 더 효율적으로 처리한다.
- CUDA(Compute Unified Device Architecture)
  - NVIDIA에서 만든, GPU를 그래픽 처리 외의 범용 연산(GPGPU, General-Purpose computing on GPU)에도 활용할 수 있도록 해주는 병렬 컴퓨팅 플랫폼이자 프로그래밍 모델이다.
  - 개발자가 GPU의 수많은 코어에서 동시에 실행될 함수(커널, Kernel)를 작성하면, CUDA가 이를 GPU의 스레드들에 분배해 병렬로 실행시켜준다.
  - 딥러닝 프레임워크(PyTorch, TensorFlow 등)들이 내부적으로 CUDA를 활용해 대규모 행렬 연산(GPU 병렬 처리)을 가속화한다.

## 자료구조 - 배열과 연결 리스트
- 배열(Array)이란?
  - 동일한 타입의 데이터를 메모리상에 연속된 공간에 나열하여 저장하는 자료구조이다.
  - 인덱스를 통해 특정 위치의 주소를 바로 계산할 수 있어(base address + index * size), 조회(접근)가 O(1)로 매우 빠르다.
  - 중간에 데이터를 삽입/삭제하려면 뒤따르는 원소들을 모두 한 칸씩 이동시켜야 하므로 O(n)이 소요된다.
  - 크기가 고정되어 있어(정적 배열), 선언된 크기를 초과하는 데이터를 저장할 수 없다는 제약이 있다. (자바의 `ArrayList`처럼 내부적으로 배열을 두고, 공간이 부족해지면 더 큰 배열로 복사하여 동적으로 크기를 늘려주는 구현도 널리 쓰인다.)
- 연결 리스트(Linked List)란?
  - 데이터를 담은 노드(Node)들이 다음 노드를 가리키는 포인터(참조)로 연결되어 있는 자료구조로, 메모리상에 연속적으로 저장될 필요가 없다.
  - 특정 위치에 삽입/삭제할 때는 앞뒤 노드의 참조만 변경하면 되므로 O(1)이지만(위치를 알고 있다는 전제 하에), 원하는 위치의 노드를 찾으려면 처음부터 순차적으로 탐색해야 하므로 조회는 O(n)이 걸린다.
  - 단일 연결 리스트(다음 노드만 참조), 이중 연결 리스트(이전/다음 노드 모두 참조), 원형 연결 리스트 등의 변형이 있다.
- 배열 vs 연결 리스트
  - 조회가 빈번하고 크기 변경이 적다면 배열이, 삽입/삭제가 빈번하다면 연결 리스트가 유리하다.
  - 배열은 메모리에 연속적으로 저장되어 캐시 지역성(Cache Locality)이 좋아 순차 접근 시 실제 성능이 더 뛰어난 경우가 많은 반면, 연결 리스트는 노드가 메모리 여기저기 흩어져 있어 캐시 효율이 떨어질 수 있다.

## 자료구조 - 스택과 큐
- 스택(Stack)이란?
  - 마지막에 들어온 데이터가 가장 먼저 나가는 LIFO(Last In First Out) 구조의 자료구조이다.
  - 데이터를 넣는 `push()`, 가장 최근에 넣은 데이터를 꺼내는 `pop()`, 꺼내지 않고 확인만 하는 `peek()` 연산을 제공하며, 모두 O(1)에 처리된다.
  - 함수 호출 시 호출 정보를 저장하는 콜 스택(Call Stack), 괄호 짝 맞추기, 실행 취소(Undo) 기능, DFS(깊이 우선 탐색)의 구현 등에 활용된다.
- 큐(Queue)란?
  - 먼저 들어온 데이터가 먼저 나가는 FIFO(First In First Out) 구조의 자료구조이다.
  - 데이터를 뒤에 추가하는 `enqueue()`(offer), 앞에서 꺼내는 `dequeue()`(poll) 연산을 제공한다.
  - 작업 대기열(큐잉 시스템), 프린터 작업 대기열, BFS(너비 우선 탐색)의 구현 등에 활용된다.
- 변형된 큐
  - 원형 큐(Circular Queue) : 배열 기반 큐에서 앞쪽이 비워진 공간을 재활용하기 위해, 배열의 끝과 처음을 논리적으로 연결한 구조이다.
  - 우선순위 큐(Priority Queue) : FIFO가 아니라, 우선순위가 높은 데이터가 먼저 나가는 구조로, 내부적으로 힙(Heap)을 이용해 구현하는 경우가 많다.
  - 데크(Deque, Double-Ended Queue) : 양쪽 끝에서 모두 삽입/삭제가 가능한 자료구조로, 스택과 큐를 모두 구현하는 데 사용할 수 있다.

## 자료구조 - 해시 테이블
- 해시 테이블(Hash Table)이란?
  - 키(Key)를 해시 함수(Hash Function)에 통과시켜 나온 해시 값을 배열의 인덱스로 사용해, 데이터를 저장하고 조회하는 자료구조이다.
  - 평균적으로 조회/삽입/삭제 모두 O(1)의 시간 복잡도를 가져, 빠른 검색이 필요한 상황에서 널리 사용된다. (자바의 `HashMap`, `HashSet`이 대표적이다.)
- 해시 충돌(Hash Collision)이란?
  - 서로 다른 키가 같은 해시 값(인덱스)으로 매핑되는 현상이다. 해시 함수의 출력 범위는 한정적이지만 입력(키)의 종류는 무한하기 때문에 충돌은 필연적으로 발생할 수 있다.
- 해시 충돌 해결 방법
  - 체이닝(Separate Chaining) : 같은 인덱스에 충돌이 발생하면, 해당 인덱스에 연결 리스트(또는 트리)로 여러 데이터를 이어 붙여 저장하는 방식이다. 자바의 `HashMap`이 이 방식을 사용하며, 하나의 버킷에 쌓인 데이터가 일정 개수(8개)를 넘으면 연결 리스트를 트리(Red-Black Tree)로 전환해 최악의 경우에도 O(log n)을 보장한다.
  - 개방 주소법(Open Addressing) : 충돌이 발생하면 다른 빈 공간을 찾아 데이터를 저장하는 방식이다. (선형 탐사, 제곱 탐사, 이중 해싱 등)
- 좋은 해시 함수의 조건
  - 입력값이 조금만 달라져도 해시 값이 크게 달라져(눈사태 효과), 값이 특정 구간에 몰리지 않고 골고루 분산되어야 충돌 가능성을 낮출 수 있다.
  - 동일한 키에 대해서는 항상 동일한 해시 값을 반환해야 한다. (일관성)

## 자료구조 - 트리와 이진 탐색 트리 (BST, AVL, Red-Black Tree)
- 트리(Tree)란?
  - 하나의 루트 노드에서 시작해 여러 자식 노드로 뻗어나가는, 계층적인 구조를 가진 비선형 자료구조이다. 노드 간에 사이클이 없다는 특징이 있다.
  - 파일 시스템의 디렉터리 구조, HTML DOM 트리, 조직도 등이 트리 구조로 표현될 수 있다.
- 이진 탐색 트리(BST, Binary Search Tree)란?
  - 각 노드가 최대 2개의 자식을 가지며, "왼쪽 자식은 부모보다 작고, 오른쪽 자식은 부모보다 크다"는 규칙을 만족하는 트리이다.
  - 이 규칙 덕분에 특정 값을 찾을 때 현재 노드와 비교해 왼쪽/오른쪽 중 한쪽만 탐색하면 되므로, 평균적으로 O(log n)의 시간 복잡도로 탐색/삽입/삭제가 가능하다.
  - 다만 데이터가 정렬된 순서대로 삽입되는 등 특정 상황에서는 트리가 한쪽으로 치우쳐(편향 트리) 사실상 연결 리스트와 같은 형태가 되어, 최악의 경우 O(n)까지 성능이 저하될 수 있다는 단점이 있다.
- AVL 트리란?
  - 모든 노드에 대해 왼쪽/오른쪽 서브트리의 높이 차이가 1 이하가 되도록 삽입/삭제 시마다 균형을 맞추는(회전, Rotation) 자가 균형 이진 탐색 트리이다.
  - 균형이 엄격하게 유지되어 탐색 성능(O(log n))이 항상 보장되지만, 삽입/삭제마다 균형을 맞추는 비용(회전 연산)이 상대적으로 크다.
- Red-Black Tree란?
  - 각 노드를 빨간색 또는 검은색으로 칠하고, 몇 가지 규칙(루트는 검은색, 빨간 노드의 자식은 모두 검은색, 모든 리프까지의 검은 노드 수가 동일 등)을 통해 균형을 유지하는 자가 균형 이진 탐색 트리이다.
  - AVL 트리보다는 균형 기준이 느슨해서 삽입/삭제 시 재조정 비용이 더 적은 대신, 탐색 성능은 AVL보다 약간 떨어질 수 있다. 삽입/삭제가 빈번한 경우에 유리해 자바의 `TreeMap`, `HashMap`의 체이닝(리스트→트리 전환) 등에서 사용된다.

## 자료구조 - 힙과 우선순위 큐
- 힙(Heap)이란?
  - 부모 노드와 자식 노드 사이에 항상 일정한 대소 관계가 성립하는 완전 이진 트리(Complete Binary Tree)이다.
  - 최대 힙(Max Heap) : 부모 노드의 값이 항상 자식 노드보다 크거나 같다. 루트에는 항상 전체 중 최댓값이 위치한다.
  - 최소 힙(Min Heap) : 부모 노드의 값이 항상 자식 노드보다 작거나 같다. 루트에는 항상 전체 중 최솟값이 위치한다.
  - 완전 이진 트리의 특성을 이용해 배열만으로도 구현할 수 있으며(부모/자식 인덱스를 산술적으로 계산), 삽입/삭제 모두 O(log n)의 시간 복잡도를 가진다.
- 우선순위 큐(Priority Queue)란?
  - 데이터를 저장된 순서가 아니라, 우선순위에 따라 꺼낼 수 있는 자료구조로, 힙을 이용해 구현하는 것이 가장 일반적이다.
  - 자바에서는 `PriorityQueue` 클래스를 제공하며, 기본적으로 최소 힙으로 동작하여 `poll()` 호출 시 가장 작은 값을 꺼낸다. 생성자에 `Comparator`를 전달하면 최대 힙 등 원하는 정렬 기준으로 동작시킬 수 있다.
- 활용 사례
  - 데이터 중 최댓값/최솟값을 반복적으로 꺼내야 하는 상황(작업 스케줄링, 다익스트라 최단 경로 알고리즘 등)에 사용된다.
  - 정렬되지 않은 배열 전체를 매번 정렬(O(n log n))하는 대신, 힙을 이용하면 최댓값/최솟값 하나를 꺼내는 데 O(log n)만 소요되어 "상위 K개" 같은 문제를 더 효율적으로 풀 수 있다.

## 자료구조 - 그래프
- 그래프(Graph)란?
  - 정점(Vertex, Node)과 정점을 연결하는 간선(Edge)으로 이루어진 비선형 자료구조로, 트리와 달리 사이클이 존재할 수 있고 루트라는 개념도 없다.
  - 방향 그래프(Directed Graph) : 간선에 방향이 있어 A→B 연결이 B→A를 의미하지 않는다. (예: 팔로우 관계)
  - 무방향 그래프(Undirected Graph) : 간선에 방향이 없어 양방향으로 연결된 것으로 간주한다. (예: 친구 관계)
  - 가중치 그래프(Weighted Graph) : 간선마다 비용(가중치)이 부여되어 있다. (예: 지도의 도로와 거리)
- 그래프의 표현 방법
  - 인접 행렬(Adjacency Matrix) : 정점 개수만큼의 2차원 배열을 이용해, `matrix[i][j]`가 i와 j 사이 간선의 존재(또는 가중치)를 나타낸다. 두 정점의 연결 여부를 O(1)에 확인할 수 있지만, 정점 수가 많아질수록 메모리 사용량이 O(V²)로 급격히 늘어난다.
  - 인접 리스트(Adjacency List) : 각 정점마다 자신과 연결된 정점들의 리스트를 저장한다. 실제 간선 수만큼만 메모리를 사용해 희소 그래프(간선이 적은 그래프)에 효율적이지만, 두 정점의 연결 여부를 확인하려면 리스트를 순회해야 한다.
- 그래프 탐색/활용
  - DFS(깊이 우선 탐색), BFS(너비 우선 탐색)를 이용해 그래프의 모든 정점을 순회하거나 특정 경로를 찾을 수 있다.
  - 최단 경로를 구하는 다익스트라(Dijkstra), 벨만-포드(Bellman-Ford) 알고리즘, 최소 신장 트리를 구하는 크루스칼(Kruskal), 프림(Prim) 알고리즘 등이 그래프를 기반으로 한 대표적인 알고리즘이다.
  - 소셜 네트워크의 친구 관계, 지도/내비게이션의 길찾기, 웹 페이지 간 링크 구조 등 현실의 많은 문제가 그래프로 모델링된다.

## 정렬 알고리즘
- 버블 정렬(Bubble Sort) - O(n²)
  - 인접한 두 원소를 비교하여 순서가 잘못되어 있으면 교환하는 과정을 반복해, 가장 큰(또는 작은) 값을 뒤로 하나씩 보내는 방식이다. 구현이 단순하지만 비효율적이다.
- 선택 정렬(Selection Sort) - O(n²)
  - 매 순회마다 남은 범위에서 최솟값(또는 최댓값)을 찾아, 맨 앞(정렬되지 않은 부분의 시작)과 교환하는 방식이다.
- 삽입 정렬(Insertion Sort) - O(n²)
  - 이미 정렬된 부분에 새로운 원소를 적절한 위치에 삽입해 넣는 방식이다. 데이터가 거의 정렬되어 있는 경우에는 O(n)에 가깝게 동작할 수 있어 실무에서도 작은 데이터셋이나 부분 정렬에 종종 사용된다.
- 병합 정렬(Merge Sort) - O(n log n)
  - 배열을 더 이상 나눌 수 없을 때까지 절반씩 재귀적으로 나눈 뒤, 나누어진 부분들을 정렬된 상태로 병합(Merge)해나가는 분할 정복(Divide and Conquer) 방식이다.
  - 항상 O(n log n)의 안정적인 성능을 보장하고, 같은 값의 상대적 순서가 유지되는 안정 정렬(Stable Sort)이지만, 병합 과정에서 원본과 동일한 크기의 추가 배열이 필요해 공간 복잡도가 O(n)이다.
- 퀵 정렬(Quick Sort) - 평균 O(n log n)
  - 기준값(Pivot)을 하나 선택해, 피벗보다 작은 값은 왼쪽으로, 큰 값은 오른쪽으로 분할한 뒤 각 부분을 재귀적으로 정렬하는 분할 정복 방식이다.
  - 평균적으로는 매우 빠르고 추가 메모리도 거의 사용하지 않아(제자리 정렬, In-place) 실무에서 가장 많이 사용되는 정렬 중 하나이지만, 피벗을 잘못 선택하면(이미 정렬된 배열에서 항상 첫 원소를 피벗으로 선택하는 경우 등) 최악의 경우 O(n²)까지 성능이 저하될 수 있다.
- 힙 정렬(Heap Sort) - O(n log n)
  - 배열을 힙으로 구성한 뒤, 루트(최댓값 또는 최솟값)를 하나씩 꺼내어 정렬하는 방식이다. 항상 O(n log n)을 보장하고 추가 메모리가 거의 필요 없지만, 안정 정렬은 아니다.
- 실무에서의 정렬
  - 자바의 `Arrays.sort()`는 기본 타입 배열에는 퀵 정렬(또는 듀얼 피벗 퀵 정렬)을, 객체 배열에는 안정성이 보장되는 병합 정렬 기반의 팀소트(TimSort)를 사용하는 등, 데이터 타입과 상황에 맞게 알고리즘을 다르게 적용한다.

## 탐색 알고리즘 (완전 탐색, 이진 탐색, DFS/BFS)
- 완전 탐색(Brute-Force)이란?
  - 가능한 모든 경우의 수를 하나하나 확인하여 답을 찾는 방식이다. 구현이 단순하고 정확성을 보장할 수 있지만, 경우의 수가 많아지면 시간 복잡도가 급격히 커져(O(n²), O(2ⁿ) 등) 비효율적일 수 있다.
- 이진 탐색(Binary Search) - O(log n)
  - 정렬된 배열에서, 중간값과 찾고자 하는 값을 비교해 탐색 범위를 절반씩 줄여나가는 방식이다.
  - 반드시 정렬된 데이터에서만 사용할 수 있다는 전제가 필요하다.
  - ``` java
    int binarySearch(int[] arr, int target) {
        int left = 0, right = arr.length - 1;
        while (left <= right) {
            int mid = (left + right) / 2;
            if (arr[mid] == target) return mid;
            else if (arr[mid] < target) left = mid + 1;
            else right = mid - 1;
        }
        return -1;
    }
    ```
- DFS(깊이 우선 탐색, Depth-First Search)
  - 한 방향으로 갈 수 있는 만큼 끝까지 탐색하다가, 더 이상 갈 곳이 없으면 이전 갈림길로 되돌아가(백트래킹) 다른 방향을 탐색하는 방식이다.
  - 재귀 함수 또는 스택(Stack)을 이용해 구현하며, 모든 경로를 찾거나 백트래킹이 필요한 문제(미로 찾기, 조합 탐색 등)에 적합하다.
- BFS(너비 우선 탐색, Breadth-First Search)
  - 시작 지점에서 가까운 노드부터 순서대로(레벨 단위로) 탐색해나가는 방식이다.
  - 큐(Queue)를 이용해 구현하며, 가중치가 없는 그래프에서 최단 경로를 찾는 문제에 적합하다. (가장 먼저 목적지에 도달했을 때가 곧 최단 거리이기 때문)
- DFS vs BFS
  - DFS는 스택(재귀)을 이용해 "깊게" 파고드는 방식이고, BFS는 큐를 이용해 "넓게" 퍼져나가는 방식이라는 차이가 있다. 모든 경로/조합을 찾아야 한다면 DFS를, 최단 경로를 찾아야 한다면 BFS를 선택하는 것이 일반적이다.

## 동적 계획법(DP)과 그리디 알고리즘
- 동적 계획법(Dynamic Programming, DP)이란?
  - 큰 문제를 작은 부분 문제(Subproblem)로 나누고, 그 부분 문제의 해를 저장해두었다가 재사용함으로써 중복 계산을 피하는 알고리즘 설계 기법이다.
  - DP를 적용하려면 "최적 부분 구조(Optimal Substructure, 부분 문제의 최적해로 전체 문제의 최적해를 구성할 수 있음)"와 "중복되는 부분 문제(Overlapping Subproblems, 동일한 부분 문제가 여러 번 반복해서 등장함)"라는 두 조건을 만족해야 한다.
- DP의 구현 방식
  - 메모이제이션(Memoization, Top-Down) : 재귀적으로 문제를 풀되, 이미 계산한 부분 문제의 결과를 캐시(배열, Map 등)에 저장해두고, 다시 호출되면 캐시에 저장된 값을 즉시 반환한다.
  - 타뷸레이션(Tabulation, Bottom-Up) : 가장 작은 부분 문제부터 차례로 계산해서 테이블(배열)에 채워나가며, 최종적으로 전체 문제의 답을 구한다. 재귀 호출 오버헤드가 없어 일반적으로 더 빠르다.
  - 예: 피보나치수열을 단순 재귀로 풀면 동일한 부분 문제가 기하급수적으로 중복 호출(O(2ⁿ))되지만, 계산 결과를 캐싱하면 O(n)으로 해결할 수 있다.
- 그리디 알고리즘(Greedy Algorithm)이란?
  - 매 선택의 순간마다 지금 당장 가장 좋아 보이는 선택(지역 최적해, Local Optimum)을 하는 방식으로, 그 선택들을 모았을 때 전체적으로도 최적해(전역 최적해, Global Optimum)가 되기를 기대하는 알고리즘이다.
  - DP보다 구현이 단순하고 빠르지만, 모든 문제에 그리디 방식이 통하는 것은 아니며, "탐욕적 선택 속성(Greedy Choice Property, 매 순간의 최선의 선택이 전체 최적해로 이어짐)"이 성립하는 문제에만 적용할 수 있다. (예: 동전 교환 문제는 동전의 단위 구성에 따라 그리디로 최적해를 구할 수 없는 경우가 있다.)
- DP vs 그리디
  - DP는 모든 부분 문제의 해를 비교/저장하며 최적해를 보장하는 반면, 그리디는 이전 선택을 돌아보지 않고 각 단계에서 최선이라 판단되는 하나의 선택만 하기 때문에 더 빠르지만 항상 최적해를 보장하지는 않는다는 차이가 있다.

## 동시성(Concurrency)과 병렬성(Parallelism)
- 동시성(Concurrency)이란?
  - 여러 작업이 "동시에 진행되는 것처럼" 보이도록 처리하는 것을 의미한다. 실제로는 하나의 CPU 코어가 여러 작업을 매우 짧은 시간 단위로 번갈아 가며 실행(Context Switching)하는 방식으로도 동시성을 구현할 수 있다.
  - 싱글 코어 환경에서도 동시성은 구현 가능하다.
- 병렬성(Parallelism)이란?
  - 여러 작업을 물리적으로 "실제로 동시에" 실행하는 것을 의미하며, 이를 위해서는 멀티 코어(또는 멀티 프로세서) 환경이 반드시 필요하다.
- 핵심 차이
  - 동시성은 여러 작업을 다루는 방식(구조)에 대한 개념이고, 병렬성은 여러 작업을 실제로 동시에 실행하는 것(실행)에 대한 개념이다.
  - 동시성은 병렬성 없이도(싱글 코어에서의 멀티태스킹처럼) 구현할 수 있지만, 병렬성을 구현하려면 동시성 있는 구조(작업을 여러 단위로 나누는 것)가 전제되어야 하는 경우가 많다.
  - 비유하자면, 한 명의 요리사가 여러 요리를 조금씩 번갈아 가며 만드는 것이 동시성이고, 여러 명의 요리사가 각자 다른 요리를 동시에 만드는 것이 병렬성이다.
- 자바에서의 예시
  - 자바의 `ExecutorService`로 적은 수의 스레드가 많은 작업을 번갈아 처리하도록 구성하는 것은 동시성에 가깝고, 멀티 코어 환경에서 `ForkJoinPool`을 이용해 하나의 큰 작업을 여러 코어가 실제로 동시에 나누어 처리하는 것은 병렬성의 예시라고 볼 수 있다.

## 컴파일러와 인터프리터
- 컴파일러(Compiler)란?
  - 소스 코드 전체를 한 번에 분석하여, 실행 가능한 기계어(또는 중간 코드)로 미리 번역해두는 번역기이다. (예: C, C++)
  - 실행 전에 컴파일이라는 별도의 단계가 필요하지만, 번역이 미리 완료되어 있어 실행 속도가 빠르고, 컴파일 시점에 문법 오류 등을 미리 발견할 수 있다.
- 인터프리터(Interpreter)란?
  - 소스 코드를 한 줄씩(또는 한 문장씩) 그때그때 해석하면서 바로 실행하는 방식이다. (예: Python, JavaScript)
  - 별도의 컴파일 단계 없이 즉시 실행할 수 있어 개발/테스트 사이클이 빠르지만, 실행할 때마다 매번 해석하는 과정을 거쳐야 해서 컴파일 방식보다 일반적으로 실행 속도가 느리다.
- 자바는 컴파일 언어인가, 인터프리터 언어인가?
  - 자바는 두 방식을 혼합한 하이브리드 방식을 사용한다. `javac` 컴파일러가 소스 코드를 플랫폼에 독립적인 중간 코드인 바이트코드(.class)로 먼저 컴파일하고, 이 바이트코드를 JVM이 실행 시점에 한 줄씩 해석(인터프리팅)하며 실행한다.
  - 다만 인터프리팅 방식만으로는 성능이 느리기 때문에, JVM은 자주 반복 실행되는 코드(Hot Spot)를 감지해 JIT(Just-In-Time) 컴파일러를 통해 실제 기계어로 미리 컴파일해두고 이후에는 컴파일된 기계어를 바로 실행하여 성능을 높인다.

## 프로그래밍 패러다임 (절차적, 객체지향, 함수형)
- 절차적 프로그래밍(Procedural Programming)
  - 프로그램을 일련의 순차적인 명령어(절차, 함수)의 흐름으로 작성하는 방식이다. 데이터와 그 데이터를 처리하는 함수가 분리되어 있는 것이 특징이다. (예: C)
  - 작은 규모의 프로그램에서는 직관적이지만, 프로그램이 커질수록 데이터와 함수 간의 관계를 관리하기 어려워지고 코드 재사용이 힘들어질 수 있다.
- 객체지향 프로그래밍(Object-Oriented Programming, OOP)
  - 데이터(상태)와 그 데이터를 다루는 함수(행위)를 하나의 객체로 묶어 캡슐화하고, 객체 간의 상호작용으로 프로그램을 구성하는 방식이다. (예: Java, C++)
  - 캡슐화, 상속, 다형성, 추상화를 통해 코드의 재사용성과 유지보수성을 높이는 데 초점을 둔다.
- 함수형 프로그래밍(Functional Programming, FP)
  - 프로그램을 순수 함수(Pure Function)의 조합으로 표현하며, 상태 변경과 부수 효과(Side Effect)를 최대한 배제하는 것을 지향하는 방식이다. (예: Haskell, Clojure)
  - 순수 함수는 같은 입력에 대해 항상 같은 출력을 반환하며 외부 상태를 변경하지 않기 때문에, 함수의 동작을 예측하기 쉽고 테스트가 용이하며 멀티스레드 환경에서도 안전(Thread-Safe)하다.
  - 함수를 값처럼 다룰 수 있어(일급 객체, First-Class Citizen), 함수를 다른 함수의 인자로 전달하거나 반환값으로 사용할 수 있다.
- 자바와 패러다임
  - 자바는 본질적으로 객체지향 언어이지만, Java 8부터 람다식과 스트림 API를 도입하여 함수형 프로그래밍 스타일(멀티 패러다임)도 함께 지원하게 되었다.

## TDD와 리팩토링
- TDD(Test-Driven Development, 테스트 주도 개발)란?
  - 실제 기능(프로덕션 코드)을 구현하기 전에, 먼저 그 기능에 대한 테스트 코드를 작성하고, 테스트를 통과시키기 위한 최소한의 코드를 작성한 뒤, 이를 개선해나가는 개발 방법론이다.
- TDD의 순환 주기 (Red-Green-Refactor)
  - Red : 아직 구현되지 않은 기능에 대한 테스트를 먼저 작성한다. 당연히 테스트는 실패(Red)한다.
  - Green : 테스트를 통과시키기 위한 최소한의 코드를 작성한다. 완벽하지 않아도 되며, 테스트만 통과(Green)시키는 것이 목표이다.
  - Refactor : 테스트가 통과하는 상태를 유지하면서, 코드의 구조/가독성/중복을 개선한다.
- TDD의 장점
  - 테스트를 먼저 작성하는 과정에서 요구사항과 설계를 더 명확히 고민하게 되어, 자연스럽게 테스트하기 좋은(결합도가 낮은) 설계로 이어지는 경우가 많다.
  - 코드를 변경할 때마다 테스트를 통해 기존 기능이 깨지지 않았는지 즉시 검증할 수 있어, 리팩토링에 대한 심리적 부담을 줄여준다.
- 리팩토링(Refactoring)이란?
  - 소프트웨어의 겉으로 보이는 동작(기능)은 그대로 유지하면서, 내부의 코드 구조를 개선하는 작업을 의미한다. 코드의 가독성을 높이고, 중복을 제거하고, 유지보수를 쉽게 만드는 것이 목적이다.
  - 리팩토링은 기능 변경이 아니기 때문에, 충분한 테스트 코드가 뒷받침되어야 "동작이 바뀌지 않았음"을 안전하게 확인하며 진행할 수 있다.
- Ref.

## 클린 아키텍처와 DDD
- 클린 아키텍처(Clean Architecture)란?
  - Robert C. Martin(Uncle Bob)이 제시한 아키텍처 원칙으로, 비즈니스 로직(도메인)을 가장 안쪽에 두고, 바깥쪽으로 갈수록 UI, DB, 프레임워크 등 세부 구현 기술을 배치하는 계층형 구조이다.
  - 핵심 규칙은 "의존성은 항상 바깥쪽에서 안쪽으로만 향해야 한다(Dependency Rule)"는 것으로, 안쪽의 도메인 로직은 바깥쪽의 구체적인 기술(DB, 프레임워크 등)에 대해 전혀 알지 못하도록 설계한다.
  - 이를 통해 특정 프레임워크나 데이터베이스에 종속되지 않는, 오래 유지보수 가능한 소프트웨어를 만드는 것을 목표로 한다. (헥사고날 아키텍처와 유사한 지향점을 공유한다.)
- DDD(Domain-Driven Design, 도메인 주도 설계)란?
  - 소프트웨어가 해결하고자 하는 비즈니스 영역(도메인)에 대한 깊은 이해를 바탕으로, 도메인 모델을 중심에 두고 설계를 진행하는 개발 방법론이다.
  - 개발자와 도메인 전문가(기획자 등)가 공통으로 사용하는 언어인 유비쿼터스 언어(Ubiquitous Language)를 정립하여, 코드와 실제 비즈니스 용어 사이의 괴리를 줄이는 것을 중요하게 다룬다.
- DDD의 주요 개념
  - Entity : 고유한 식별자를 가지며, 생명주기 동안 속성이 변해도 동일성이 유지되는 객체.
  - Value Object : 식별자 없이 속성 값 자체로 동일성을 판단하는 불변 객체.
  - Aggregate : 연관된 Entity와 Value Object를 하나의 묶음으로 간주하고, 그 묶음의 일관성을 책임지는 루트(Aggregate Root)를 통해서만 외부에서 접근하도록 하는 경계이다.
  - Repository : Aggregate를 저장하고 조회하는 역할을 추상화한 인터페이스로, 실제 영속성 기술(JPA 등)과 도메인 모델을 분리하는 역할을 한다.

## Git과 브랜치 전략
- Git이란?
  - 소스 코드의 변경 이력을 추적하고 관리하는 분산 버전 관리 시스템(DVCS)으로, 각 개발자가 전체 저장소의 이력을 로컬에 가지고 있어 중앙 서버 없이도 커밋/브랜치 등의 작업을 수행할 수 있다.
- Git의 기본 작업 흐름
  - Working Directory(작업 디렉터리) → Staging Area(`git add`) → Repository(`git commit`)의 단계를 거쳐 변경 사항이 기록된다.
  - 원격 저장소와는 `git push`(로컬 변경사항 전송), `git pull`(원격 변경사항 가져오기+병합)로 동기화한다.
- Git Flow
  - `main`(또는 `master`, 배포 가능한 상태), `develop`(다음 출시를 위한 개발 통합 브랜치), `feature`(기능 개발), `release`(배포 준비), `hotfix`(긴급 수정) 등 여러 종류의 브랜치를 목적에 따라 나누어 사용하는 전략이다.
  - 체계적이지만 브랜치 종류가 많고 과정이 복잡해, 빠른 배포 주기를 가진 팀에는 다소 무거울 수 있다.
- GitHub Flow
  - `main` 브랜치 하나만을 항상 배포 가능한 상태로 유지하고, 새로운 작업은 `main`에서 분기한 `feature` 브랜치에서 진행한 뒤 Pull Request를 통해 리뷰와 테스트를 거쳐 다시 `main`에 병합하는 단순한 전략이다.
  - 지속적 배포(CD)를 지향하는 팀에서 널리 사용된다.
- Trunk-Based Development
  - 하나의 메인 브랜치(trunk)에 짧은 생명주기의 브랜치(또는 직접 커밋)로 매우 자주 통합(병합)하는 전략으로, 브랜치가 오래 유지될수록 커지는 병합 충돌을 최소화하는 데 초점을 둔다.
- 병합(merge) vs 리베이스(rebase)
  - `merge`는 두 브랜치의 이력을 그대로 보존하며 새로운 병합 커밋을 만드는 방식이고, `rebase`는 브랜치의 커밋들을 다른 브랜치의 최신 커밋 뒤로 옮겨 붙여 하나의 선형적인 이력을 만드는 방식이다. rebase는 이력이 깔끔해지지만, 이미 공유(push)된 브랜치에 사용하면 커밋 해시가 바뀌어 협업 중인 다른 사람과 충돌이 발생할 수 있어 주의가 필요하다.

## 쿠버네티스(Kubernetes)
- 쿠버네티스(Kubernetes, K8s)란?
  - 여러 대의 서버(노드)에 걸쳐 컨테이너화된 애플리케이션의 배포, 확장, 운영을 자동화해주는 오픈소스 컨테이너 오케스트레이션 플랫폼이다.
  - MSA 환경에서 수십~수백 개에 달하는 컨테이너를 수동으로 관리하는 것은 현실적으로 불가능하기 때문에, 쿠버네티스가 컨테이너의 배포/스케일링/장애 복구 등을 대신 자동화해준다.
- 핵심 개념
  - Pod : 쿠버네티스에서 배포할 수 있는 가장 작은 단위로, 하나 이상의 컨테이너를 포함한다. 같은 Pod 안의 컨테이너들은 네트워크와 스토리지를 공유한다.
  - Node : Pod가 실제로 실행되는 물리/가상 서버이다.
  - Deployment : Pod의 원하는 개수(복제본, Replica)와 배포 방식(롤링 업데이트 등)을 선언적으로 관리하는 리소스로, Pod가 비정상 종료되면 자동으로 재생성해준다.
  - Service : 여러 개의 Pod에 안정적인 네트워크 접근 경로(고정 IP, DNS 이름)를 제공하고, 그 Pod들 사이로 트래픽을 로드밸런싱해준다. Pod는 재시작될 때마다 IP가 바뀔 수 있기 때문에 Service를 통한 간접 접근이 필요하다.
  - ConfigMap / Secret : 설정 값이나 민감한 정보(비밀번호, 인증키 등)를 컨테이너 이미지와 분리하여 관리할 수 있도록 해준다.
- 쿠버네티스의 주요 기능
  - 셀프 힐링(Self-Healing) : 컨테이너가 다운되면 자동으로 재시작하거나 새로운 Pod로 교체한다.
  - 오토 스케일링(Auto Scaling) : CPU/메모리 사용률 등의 지표에 따라 Pod 개수를 자동으로 늘리거나 줄인다.
  - 롤링 업데이트(Rolling Update) : 서비스 중단 없이, 기존 Pod를 순차적으로 새 버전으로 교체 배포한다.
  - 서비스 디스커버리와 로드밸런싱 : Service를 통해 Pod의 위치가 바뀌어도 일관된 방식으로 통신할 수 있게 해준다.
